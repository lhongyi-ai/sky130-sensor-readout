# project1 补查包 v1.1.0

第一版报告已收到。第一版漏收 Spectre CDF 映射，模型扫描也被大量器件文件占满；本版修正这两项。不是用户操作错误。

本包只读取环境、CDF、已有 symbol 和模型/规则文件的名称与结构元数据。不创建或修改电路，不执行 PCell 回调、不安装软件、不运行仿真，不打包 PDK、规则正文或许可证。

## 1 上传和解压（Linux 终端）

把 project1_probe_v1.1.0.zip 上传到 ~/cadence_skywater/，执行：

```bash
cd ~/cadence_skywater
unzip -n project1_probe_v1.1.0.zip
cd project1_handoff/probe_v1_1
bash run.sh probe
```

目录独立于 project1 库和第一版 probe，勿解压进 OpenAccess 库数据库。

## 2 在已经打开的 Virtuoso 中运行（CIW）

终端会打印本次专用的 `load("…/load_probe.il")` 命令。完整复制这一行到 CIW 底部输入栏，按 Enter。不要复制上次的命令。

CIW 是显示启动信息和日志的 Command Interpreter Window，通常顶部有 File、Tools、Options、Help 菜单。输入栏位于日志区下方；Library Manager 的库列表和 Linux 终端都不是 CIW。

成功标志：`PROJECT1_PROBE_COMPLETE`。若有错误，保留错误文字，仍执行下一步回传部分报告。

## 3 打包回传（原 Linux 终端）

```bash
cd ~/cadence_skywater/project1_handoff/probe_v1_1
bash run.sh collect
```

下载终端打印的 `project1_report_*.zip` 并发回本任务。不是再次发送检查包。

## 如何确认两项信息

- 器件映射：报告中的 SPECTRE_CDF 提供模型/元件名、termOrder、instParameters、netlistProcedure、propMapping；CDF_PARAMETER 提供 w/fw/l/fingers/m/simW/simM 等定义；SYMBOL_TERMINAL 提供实际端口。它们是生成器适配依据，不能单独证明回调行为和仿真尺寸。
- 模型入口：cadence_pdk_index.json 和 linux_report.json 记录顶层模型候选及 section 名称。存在某个 tt 字段不等于模型已可用，仍由 Codex 核对目标器件和入口关系。
- 最终验证：生成一个 W=5 µm、L=0.5 µm、fingers=1、m=1 的 NMOS 测试台，检查 Cadence 导出网表中的 D/G/S/B、宽长、倍乘、模型 include/section，然后实际运行 Spectre DC。许可证与模型可用性以这次运行结果为准。

本地检查可验证脚本结构与报告逻辑；SKILL 运行及学校 PDK 行为仍待 Linux 端验证。若补查仍缺信息，回传缺失状态，勿自行猜模型路径。
