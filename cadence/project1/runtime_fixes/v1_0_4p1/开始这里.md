# 基础设计执行补丁 1.0.4p1

本补丁适用于已经生成 `p1b_ota_legacy_r4` 等原理图的 `basic_design_v1_0_4`。只更新运行入口；不执行 SKILL，不更改 `project1` 库、器件尺寸或测试门槛。请勿重新 `load(create.il)`。

## 已确认的原因

学校 OCEAN 返回的文件是本次运行目录内的 `native/p1b_tb_res/spectre/schematic/netlist/input.scs`。同一目录中的 `netlist` 是顶层电路内容，`ihnl/cds0/netlist` 是内部生成文件。旧脚本递归搜索所有同名文件，因找到两份而误停。

新入口解析 `netlist_return.txt` 中 OCEAN 返回的绝对路径，确认它仍在本次独立运行目录内，然后使用该 `input.scs` 同目录的顶层 `netlist`。不按修改时间、文件大小或搜索顺序选择；继续执行原有连接、端口、模型和参数检查。另保留 `native_input.scs` 及 `native_selection.json`，记录选择依据和输入哈希。

## 上传与安装（全部在 Linux 终端）

1. 把 `project1_basic_runtime_fix_v1.0.4p1.zip` 上传到 `~/cadence_skywater/`，与原完整 ZIP 放在一起。
2. 在当前已经配好 Cadence 环境与许可证地址的终端中执行：

```bash
cd ~/cadence_skywater
unzip -n project1_basic_runtime_fix_v1.0.4p1.zip
cd project1_handoff/basic_design_v1_0_4
bash ../basic_runtime_fix_v1_0_4p1/apply.sh
```

预期出现 `P1_RUNTIME_PATCH_APPLIED: 1.0.4p1`。重复执行若文件完整则显示 `P1_RUNTIME_PATCH_ALREADY_APPLIED`；两个标志均可继续。

安装器核对原包及补丁哈希，保存原 `run.py` 和清单至 `patch_backups/v1_0_4p1/`，最后更新清单为运行补丁版。不修改你的 `site.json`，不改变已有状态或波形文件。若出现 `P1_RUNTIME_PATCH_STOPPED`，回传完整输出，不继续执行测试。

## 重新运行工艺电阻／电容测试

仍在 `basic_design_v1_0_4` 文件夹和同一个终端中执行：

```bash
bash p1_run.sh run --group passives --retry
```

`p1_run.sh` 在启动系统 Python 前移除 `LD_LIBRARY_PATH`，并保存它的值；运行器只在启动 OCEAN／Spectre 子进程时恢复这份库路径。父 Python 不再全程继承 Cadence 的 Python 库路径。已有 PATH、CDSHOME 和许可证定位环境仍由当前终端提供，本补丁不安装软件或配置许可证服务。

这条命令顺序执行电阻 DC、MIM AC、RC 阶跃。每次尝试写入新的结果目录。每项输出为：

```text
任务名  工具状态  性能状态  [错误信息]  结果目录
```

只有实际显示 `PASS PASS` 才表示该项已完成并满足当前门槛。`ENV_BLOCKED NOT_RUN` 表示还未得到可验收结果；`FAIL` 或 `REVIEW_REQUIRED` 要结合日志分析。旧失败记录继续显示，不会变成通过。

查看汇总与打包：

```bash
bash p1_run.sh summary
bash p1_run.sh collect
```

回传终端打印的 `project1_basic_report_*.zip`。包中包含新选择记录、原始顶层输入、运行日志、PSF、CSV、状态及原运行器备份清单，不包含整套 PDK 或规则库。

工艺 R/C 三项实际通过后，原流程其余入口保持一致，仅替换启动方式：

```bash
bash p1_run.sh run --group nominal
bash p1_run.sh run --group pvt
bash p1_run.sh run --group extra
```
