# Open-source Dynamic Device-Noise Qualification Probe (2026-09-10)

## Conclusion

**An intrinsic-noise engine independent of Cadence was found, but single-transistor comparisons further confirm nonequivalent model noise; it cannot directly qualify the current SKY130 ADC.**

VACASK `a9d8860929517499299b91a0300c0f8ff2ff4716`, already installed in the same fixed image, supports transient noise generated by device models. This round completes its minimum physical/reproducibility qualification checks. No new software was downloaded or installed, no arbitrary white noise was added to the ADC input, and continuous `.noise` was not presented as time-varying noise.

Machine-readable results: [qualification.json](qualification.json). `adc_noise_qualified=false` and `full_chain_sndr_qualified=false` deliberately retain the actual status.

## What was actually done

A minimum RC circuit uses a 10 kΩ resistor and 1 nF capacitor at 27 °C, with zero current excitation. The resistor model itself supplies thermal noise: installed source `devices/resistor.va` specifies noise power spectral density `4 k T / R`, without an extra random source. Theoretical infinite-bandwidth voltage variance is `kT/C = 4.1440179735e-12 V²`, approximately 2.036 µV RMS.

Simulation lasts 20 ms, discarding the first 1 ms. Before analysis, adaptive-step waveforms are interpolated onto a uniform 100 ns grid to avoid treating densely output simulation points as longer physical time. With noise enabled, `noisefmin=10 Hz` and `noisefmax=1 MHz`; the engine implements white-noise and flicker frequency ranges differently, so `noisefmin` cannot simply be treated as an ideal brick-wall high-pass. This RC check primarily targets thermal noise.

| Control | Measured voltage variance / theoretical kT/C |
|---|---:|
| Transient noise disabled | 0 |
| ZOH, seed 11, 6× oversampling | 1.05397 |
| Replay under identical conditions | 1.05397, identical complete-waveform hash |
| ZOH, seed 29 | 1.03908, different waveform |
| ZOH, 12× oversampling | 1.01937 |
| SDE, 6× oversampling | 1.04539 |

Independent small-signal noise integration of the same circuit from 10 Hz–1 MHz gives `4.1009348933e-12 V²`, close to the analytical value. This is only a cross-check for this linear time-invariant RC control and cannot be generalized to SAR ADC noise. The 20% physical-magnitude checking threshold belongs to the engine probe, not relaxed chip specifications; only two independent random seeds also do not certify statistical accuracy.

All input circuits, logs, raw waveforms, and initial failures are in `results/`. The successful RC control is fixed to `results/20260910T062307Z/`; no seed is selected to manufacture a chip PASS.

## Why dynamic noise of the SKY130 ADC has not yet been run directly

First, a minimum common-source test with one SKY130 `nfet_01v8` (W=2 µm, L=1 µm), a resistive load, and a capacitor was built. Original ngspice operating-point, small-signal-noise, and ordinary-transient analyses all completed, establishing that the current PDK and test itself work. Ordinary `.tran` output is essentially constant, while small-signal noise is nonzero; the analyses must not be conflated.

Migration of the same device was then attempted using the installed official `ng2vc` converter. The probe records these successive issues:

1. The converter does not recursively resolve relative paths from the included file's directory.
2. Some model-selection numbers are written as `54.0`, causing direct `int()` parsing to fail.
3. ngspice control commands are mistaken for devices during the converter's one-pass processing; only hardware descriptions should therefore be converted, with subsequent analyses written separately in native VACASK syntax.
4. Some `.param` expressions have addition terms after braces and fail when the converter splits on whitespace.
5. **The final substantive gap: the installed converter lacks a MOS `M` instance output function, LEVEL 54 BSIM4 mapping, and a complete path for parsing SKY130 `.N` geometry bins.**

Only independent, semantics-preserving adaptations were made for the first four issues: file lookup, integer-number text format, circuit/analysis separation, and expression parentheses. Process parameters were neither deleted nor modified. The fifth issue cannot be bypassed by suppressing errors or deleting transistors, so this round stopped at an explicit migration gap. VACASK includes `spice/bsim4v8.osdi` for transient noise, but that does not establish equivalence of all SKY130 BSIM 4.5 models, bins, mismatch, and multipliers.

PDK-derived content may be written only to dedicated container temporary directories `/tmp/sensor_noise_pdk_*`. The repository retains conversion scripts, paths, and hashes, not a converted copy of the entire PDK. Current frontend/ADC/digital source files were not changed.

## Addendum: Numerical comparison of one real SKY130 NFET, bypassing the general converter

A deeper bounded adaptation subsequently progressed beyond the general converter's syntax errors. `single_mos_numeric.py` reads the actually selected ngspice `xm:nshort_model.29`, explicitly identifying native implementation **BSIM4v5, version=4.5**. It reads 349 explicitly specified original-model parameters and 14 instance parameters individually from that bin. Unspecified defaults are not all forced to explicit values, avoiding changes to internal Given flags.

- All parameters are stored in container `/tmp/sensor_numeric_bin_*`; the repository records only hashes.
- ngspice queries return `tnom` in Kelvin, explicitly converted to Celsius when writing the model card; queried device geometry is already in meters.
- `m` is explicitly mapped to `$mfactor` according to official model source, preserving current, charge, and noise scaling semantics.
- `lintnoi` is explicitly zero in the original model, but native queries do not expose it; its original literal is retained rather than deleted.
- `level=54` is represented by the implementation selection; **version=4.5 is explicitly retained, not silently changed to 4.8.3**.

The fully expanded numeric model was first reinserted into ngspice, retaining BSIM4v5/4.5: DC-current relative error `9.89e-13`, maximum AC complex-response relative error `1.35e-13`, and maximum noise-spectrum relative error `2.72e-13`. This establishes that parameter extraction and unit conversion at this single bias point did not cause the later differences.

The same explicit parameters were then supplied to VACASK:

| Measurement | Original SKY130/ngspice | Numeric parameters/VACASK |
|---|---:|---:|
| Drain current | 4.096583762 µA | 4.096583806 µA |
| AC complex response | Reference | Maximum relative difference approximately 2.11e-9 |
| Output noise RMS, 10 Hz–100 MHz | 162.476 µV | 139.794 µV |
| Relative to original noise power spectrum | 1 | Minimum 0.4848, maximum deviation approximately 3.144 dB |

**This noise-model difference is unacceptable, even though DC and AC almost coincide.** VACASK logs explicitly warn of an unknown version and fallback to 4.8.3; corresponding official installed source implements only 4.8.0–4.8.3. This round neither modified that model rule nor deleted problematic parameters to fabricate a pass.

The same VACASK circuit completed an intrinsic transient-noise on/off demonstration: standard deviation approximately `2.22e-16 V` with noise off and `131.289 µV` with noise on. However, the enabled result comes from a nonequivalent model and **is not qualified SKY130 noise evidence**. Its 20 µs duration and 10 kHz–100 MHz noise settings cannot replace the whole low-frequency noise spectrum or complete ADC accuracy acceptance.

Evidence is fixed in `results/single_mos_20260910T063501Z/summary.json` and `numeric_equivalence.json`. All successful and failed data are retained. The explicit blocker has advanced from unsupported converter functionality to nonequivalent available-model noise. Next requires an intrinsic-noise implementation matching BSIM4v5 or a sufficiently verified, user-reviewed model-migration decision; syntax adjustments alone cannot establish completion.

## Concrete next routes independent of Cadence

1. Resolve demonstrated BSIM4v5↔4.8.3 noise nonequivalence first, then complete reviewed general SKY130→VACASK conversion, individually preserving geometry bins, µm/m scaling, MOS multipliers, model versions, local parameters, and mismatch random-variable lifecycles. Existing single-bin numeric extraction applies only to one fixed geometry and nominal instance, not a complete PDK port.
2. For this project's actual NMOS/PMOS/LVT, real resistors, and MIMs, compare DC, AC, static noise, and charge/capacitance device by device against ngspice first; a passing resistor test does not permit skipping them.
3. Verify real MOS sampling circuits: sampled noise after a long acquisition window should approach applicable kT/C; compare convergence over bandwidth, time step, and integration algorithm, and check noise off plus same/different seeds.
4. Sweep tiny inputs into the real dynamic comparator to estimate decision probabilities and input-referred noise. Preserve prior-cycle state, reset, kickback, and overload history; do not substitute arbitrary independent noise sources.
5. Complete a qualified connection between the existing SAR controller and new engine, or an equivalence-verified gate-level circuit version, before full ADC/full-chain coherent-sampling dynamic verification.
6. Do not arbitrarily reduce final bandwidth for attractive SNDR. Increase `noisefmax`, refine time steps, and add random seeds to prove convergence, including noise folding, real reference terminals, and frontend noise.

Under the engine's current time-step limit, `noisefmax=100 MHz` and oversampling 6 imply a maximum step of approximately 0.833 ns. A record of only 16,384 samples at 100 kS/s requires at least approximately 196.6 million time intervals, excluding startup and adaptive subdivision. Module qualification and method convergence are therefore necessary first; this estimate explains computational cost, not permission to reduce final sample count or noise bandwidth.

This route is **engineering work still to be implemented**, not a claim that only Cadence can physically do it. User-requested final native Cadence design and verification remain separate requirements.

## Reproduction

In the existing container `sky130-v2-resume-20260910`:

```sh
python3 /repo/v2/verification/noise_20260910/probe.py
python3 /repo/v2/verification/noise_20260910/build_report.py
python3 -m unittest discover -s /repo/v2/verification/noise_20260910 -p 'test_*.py'
```

The probe runs only one simulation process at a time; each round adds a timestamped output directory. Conversion failures are recorded separately and never change `adc_noise_qualified` to true. `build_report.py` uses a frozen historical RC-result reference; requalification requires an audited reference update, not automatic selection of the best run.
